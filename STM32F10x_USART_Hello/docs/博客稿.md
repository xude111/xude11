# STM32F103 串口通信三连：阻塞 / 中断 / DMA，顺便用 Keil 逻辑分析仪测出真实波特率

> 一块 Blue Pill、一个 USB 转 TTL、一个串口助手，把 STM32 串口最常见的三种发送方式跑一遍，最后没有示波器也不慌 —— Keil 自带的逻辑分析仪就能把波形画出来。

## 一、先把串口配好

STM32F103C8T6 的 USART1 默认引脚是 **PA9(TX) / PA10(RX)**，挂在 APB2 上，系统时钟 72 MHz 时它就是 72 MHz。

用 CubeMX 配置只需要三步：`Connectivity → USART1 → Mode = Asynchronous`，参数填 **115200 / 8 Bits / None / 1**，再切到 `NVIC Settings` 勾上 `USART1 global interrupt`。

接线记住一句话：**TX 接对方的 RX**。

```
STM32 PA9  (TX) → USB-TTL RXD
STM32 PA10 (RX) ← USB-TTL TXD
STM32 GND       ↔ USB-TTL GND
```

串口助手：115200-8-N-1、无流控、文本模式、**编码选 UTF-8**（不然全角"！"会变成方块）。

## 二、任务一：阻塞发送，故意不加延时

```c
static const uint8_t g_hello[] = "hello windows！\r\n";
volatile uint8_t g_send_enable = 1U;

while (1) {
    if (g_send_enable) {
        HAL_UART_Transmit(&huart1, (uint8_t *)g_hello,
                          sizeof(g_hello) - 1, 100);
        /* 这里故意什么都不加 */
    }
}
```

打开串口后会看到疯狂刷屏。**持续一段时间后开始丢数据**：界面卡顿、行不完整、甚至串口助手短暂无响应。

这不是 STM32 发错了。原因在于 PC 那边的链路很长：

```
USB-TTL → Windows 串口驱动缓冲区 → 串口助手 → 界面重绘/自动滚屏
```

界面重绘是最慢的一环。STM32 是"盲发"，没有 RTS/CTS 流控，上位机处理不过来也没法让它停；驱动缓冲区一满，后面的数据就直接被丢掉。

**结论：不加延时能不能丢数据，取决于上位机处理速度。** 解决思路有三种：发送之间加延时（主动降速）、启用流控、或者让上位机用更轻量的方式收（比如 Python 脚本直接存文件，不做界面刷新）。

### 加个字符控制：`#` 暂停、`*` 继续

```c
static uint8_t g_rx_byte = 0;

/* main 里挂一次接收中断 */
HAL_UART_Receive_IT(&huart1, &g_rx_byte, 1);

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART1) {
        if (g_rx_byte == '#') g_send_enable = 0;   /* 暂停 */
        if (g_rx_byte == '*') g_send_enable = 1;   /* 继续 */

        HAL_UART_Receive_IT(&huart1, &g_rx_byte, 1);  /* 必须重挂 */
    }
}
```

两个坑：`g_send_enable` 一定要加 `volatile`（中断里写、主循环里读）；`HAL_UART_Receive_IT` 是**一次性**的，不在回调里重挂就只能收到第一个字符。

## 三、任务二-1：改成中断发送

阻塞发送时 CPU 被占住 1.5 ms。改成中断方式，挂上就返回，发完进回调：

```c
/* 只启动第一次 */
HAL_UART_Transmit_IT(&huart1, (uint8_t *)g_hello, sizeof(g_hello) - 1);

while (1) { /* 主循环空转，CPU 解放了 */ }

void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART1 && g_send_enable)
        HAL_UART_Transmit_IT(&huart1, (uint8_t *)g_hello,
                             sizeof(g_hello) - 1);
}
```

现象和阻塞方式一模一样，但主循环是空的 —— 这就是中断的价值：串口在后台自己发，CPU 可以去做别的事。

## 四、任务二-3：DMA 连续发送

F103 的 **USART1_TX 固定走 DMA1 通道 4**。配置要点四个：

| 项目 | 值 |
|---|---|
| Direction | Memory → Peripheral |
| PeriphInc / MemInc | Disable / Enable |
| Data alignment | Byte / Byte |
| Mode | **DMA_CIRCULAR**（循环） |

```c
hdma_usart1_tx.Instance = DMA1_Channel4;
hdma_usart1_tx.Init.Direction = DMA_MEMORY_TO_PERIPH;
hdma_usart1_tx.Init.PeriphInc = DMA_PINC_DISABLE;
hdma_usart1_tx.Init.MemInc = DMA_MINC_ENABLE;
hdma_usart1_tx.Init.PeriphDataAlignment = DMA_PDATAALIGN_BYTE;
hdma_usart1_tx.Init.MemDataAlignment = DMA_MDATAALIGN_BYTE;
hdma_usart1_tx.Init.Mode = DMA_CIRCULAR;      /* 循环，硬件自动重装 */
HAL_DMA_Init(&hdma_usart1_tx);
__HAL_LINKDMA(huart, hdmatx, hdma_usart1_tx); /* 绑定，别漏 */

/* main 里启动一次就够了 */
HAL_UART_Transmit_DMA(&huart1, (uint8_t *)g_hello, sizeof(g_hello) - 1);
```

循环模式下 DMA 传完一遍自动回到起点重来，**CPU 完全不参与**。三种方式对比：

| 方式 | CPU 占用 | 适合场景 |
|---|---|---|
| 阻塞 | 高（全程占用） | 简单调试 |
| 中断 | 中（每串一次中断） | 一般通信 |
| DMA | 极低 | 高速、大数据量 |

## 五、任务三：没有示波器，用 Keil 逻辑分析仪测波形

### 操作步骤

1. 把 `USART_MODE` 改成中断模式（任务二-1），重新编译；
2. 魔术棒 → `Debug` → 左侧选 **Use Simulator**（别选 ST-Link）；
3. `Ctrl+F5` 进入仿真；
4. `View → Analysis Windows → Logic Analyzer`；
5. 点 `Setup...` → `New`，把信号名改成 **`PORTA.9`**，Display Type 选 `Bit`；
6. `F5` 运行，波形就出来了。

> 信号名必须写 `PORTA.9`。写成 `GPIOA.ODR.9` 或 `USART1_TX`，Keil 会提示 `Unknown Signal`。

### 波形长什么样

以发送 `'h'`（0x68 = 0110 1000）为例：

```
        ┌─┐ ┌───┐   ┌───────┐ ┌─┐
  ──────┘ └─┘   └───┘       └─┘ └──────
   空闲  起  D0 D1 D2 D3 D4 D5 D6 D7 停
```

起始位 1 位低电平 → 8 位数据（**低位先发**）→ 停止位 1 位高电平，一帧 10 位。

### 算实际波特率

在波形上量相邻两个同向跳变沿（跨 1 位）的时间：

```
Δt ≈ 8.68 μs
波特率 = 1 / Δt ≈ 115200 bps
```

对照寄存器计算：

```
USARTDIV = 72 000 000 / (16 × 115200) = 39.0625
整数部分 39 → BRR[15:4] = 0x27
小数部分 0.0625 × 16 = 1 → BRR[3:0] = 0x1
BRR = (39 << 4) | 1 = 0x271 = 625
实际波特率 = 72 000 000 / 625 = 115200 bps，误差 0
```

一帧 10 位 ≈ 86.8 μs，18 字节的 `hello windows！\r\n` 共 180 位 ≈ **1.56 ms**，和逻辑分析仪上量到的整串时间完全对得上。

## 六、踩过的坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 完全收不到数据 | TX/RX 没交叉 | PA9→RXD，PA10→TXD |
| 乱码 | 波特率不一致 / 编码不对 | 两边都 115200-8-N-1，助手选 UTF-8 |
| 发 `#` 没反应 | 没使能 USART1 中断 | NVIC 勾 `USART1 global interrupt` |
| 只能收第一个字符 | `Receive_IT` 是一次性的 | 回调末尾重挂 |
| 中断发送只发了一串 | 没在 `TxCpltCallback` 里续发 | 回调里再挂一次 |
| DMA 完全没输出 | 没开 DMA1 时钟 / 没 `__HAL_LINKDMA` | 补上时钟和绑定 |
| 逻辑分析仪 Unknown Signal | 信号名写错 | 用 `PORTA.9` |

---

## 小结

同一句话 `hello windows！`，用三种方式发出去，现象几乎一样，但**背后的 CPU 开销差了一个数量级**。串口这东西，配通只占 10% 的工作量，剩下 90% 都在想：数据量多大、CPU 还有没有余力、上位机跟不跟得上。

至于没有示波器 —— Keil 的软件仿真 + 逻辑分析仪已经把答案给出来了：**8.68 μs 位宽，115200 bps，误差为零**。
